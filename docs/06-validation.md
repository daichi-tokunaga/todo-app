# 第 6 章　入力チェック（バリデーション）

**目安：40 分**

## この章のゴール

- 空のまま送信すると「タスク名を入力してください。」と赤字で出る
- 101 文字以上は登録できない
- エラーになっても、入力した内容が消えない

## この章で学ぶこと

`$request->validate()` / `@error` / `old()`

---

## なぜ必要か

第 5 章の演習 5-A でやったとおり、いまは **空のタスクが登録できてしまいます**。

「フロント側で `required` を付ければいいのでは？」と思うかもしれませんが、
HTML の `required` は **ブラウザの開発者ツールで簡単に消せます**。
そのため、**サーバー側のチェックは必須** です。

---

## Step 6-1　コントローラでチェックする

`store()` を次のように書き換えます。

```php
    /**
     * POST /tasks  新規登録
     */
    public function store(Request $request)
    {
        $validated = $request->validate([
            'name' => 'required|max:100',
        ], [
            'name.required' => 'タスク名を入力してください。',
            'name.max'      => 'タスク名は100文字以内で入力してください。',
        ]);

        Task::create([
            'name'   => $validated['name'],
            'status' => false,
        ]);

        return redirect()->route('tasks.index');
    }
```

### `validate()` の動き

```php
$validated = $request->validate($ルール, $メッセージ);
```

- **通ったとき** … 検証済みの値だけが入った配列が返る。処理はそのまま続く
- **通らなかったとき** … **その場で処理を中断** し、元のページへ自動リダイレクト。
  エラー内容と入力値をセッションに入れてくれる

`if` 文を書かなくていいのがポイントです。

### よく使うルール

| ルール | 意味 |
| --- | --- |
| `required` | 必須 |
| `max:100` | 100 文字以内（数値なら 100 以下） |
| `min:3` | 3 文字以上 |
| `integer` | 整数であること |
| `date` | 日付として解釈できること |
| `email` | メールアドレスの形式 |
| `unique:tasks,name` | `tasks` テーブルの `name` で重複していないこと |

複数を組み合わせるときは `|` で繋ぎます（例：`required|max:100`）。

### メッセージのキーの書き方

```
'カラム名.ルール名' => 'メッセージ'
```

`name.required` は「`name` の `required` ルールに引っかかったとき」という意味です。
省略すると英語のメッセージが出ます。

## Step 6-2　エラーメッセージを画面に出す

`resources/views/tasks/index.blade.php` のフォーム部分を書き換えます。

```blade
    {{-- 追加フォーム --}}
    <div class="card">
        <form action="{{ route('tasks.store') }}" method="post">
            @csrf
            <div class="form-row">
                <input type="text" name="name" value="{{ old('name') }}" placeholder="洗濯物をたたむ...">
                <button type="submit">追加する</button>
            </div>
            @error('name')
                <p class="error">{{ $message }}</p>
            @enderror
        </form>
    </div>
```

追加したのは 2 か所です。

| 追加したもの | 意味 |
| --- | --- |
| `value="{{ old('name') }}"` | 直前に入力した値を復元する。初回表示時は空文字 |
| `@error('name') ... @enderror` | `name` にエラーがあるときだけ中身を表示。`$message` が使える |

### `old()` がないとどうなる？

エラーで戻されたとき、入力欄が空っぽになります。
100 文字近く打った直後にこれをやられると、ユーザーはかなり嫌な気持ちになります。
**フォームを作ったら `old()` をセットで書く** と覚えてください。

## 動作確認

1. **空のまま送信** → 「タスク名を入力してください。」が赤字で出る
2. **適当な長文をコピペして 101 文字以上で送信** → 「タスク名は100文字以内で入力してください。」
3. エラーが出たあと、**入力欄に打った内容が残っている**
4. 正しく入力すれば今までどおり登録できる

```bash
php artisan test --filter=ch06
```

## 参考：エラーをまとめて表示する書き方

項目が増えてきたら、こういう書き方もできます（今回は使いません）。

```blade
@if ($errors->any())
    <ul class="error">
        @foreach ($errors->all() as $error)
            <li>{{ $error }}</li>
        @endforeach
    </ul>
@endif
```

`$errors` は **すべてのビューで自動的に使える変数** です（自分で渡す必要はありません）。

## 演習

**演習 6-A**
「タスク名は 3 文字以上」というルールを追加し、
「タスク名は3文字以上で入力してください。」というメッセージを出してください。
確認できたら、このルールは外して構いません。

**演習 6-B**
同じタスク名を 2 回登録できないようにしてください。
ヒント：`unique:tasks,name` と `name.unique`。

**演習 6-C**
`value="{{ old('name') }}"` を消した状態でエラーを出し、
使い勝手がどう変わるか体感してください。**確認したら戻すこと。**

## つまずいたら

| 症状 | 原因 |
| --- | --- |
| エラーメッセージが出ない | `@error('name')` の `'name'` がフォームの `name` 属性と一致しているか確認 |
| 英語のメッセージが出る | `validate()` の第 2 引数（メッセージ配列）を渡していない、またはキーのスペルミス |
| エラーなのに登録されてしまう | `validate()` より **前** に `Task::create()` を書いていないか確認 |
| `Undefined variable $message` | `@error` ブロックの **外** で `$message` を使っている |
