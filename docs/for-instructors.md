## 教材の構成

```
README.md                     受講者向けトップページ
docs/
  00-setup.md 〜 12-advanced.md   本編（13 章）
  99-solutions.md              演習の解答例
  cheatsheet.md                artisan / Blade / Eloquent の早見表
  troubleshooting.md           エラー別の対処法
  for-instructors.md           このファイル
public/css/app.css            配布済みの CSS（Node.js 不要にするため）
tests/Feature/TodoAppTest.php  自己採点テスト（14 件）
```

リポジトリの `main` ブランチは **素の Laravel 9 + 教材** です。
`solution` ブランチに完成版のコードが、**2 つのコミットに分けて** 入っています。

```bash
git switch solution   # 完成版を見る
git log --oneline     # 2 コミット
#   第11章：型を付けて堅くする（リファクタリング後）  ← 最終形
#   完成版：Todoアプリ（第10章まで）                 ← 型を付ける前
git switch main       # 初期状態に戻る
```

第 10 章時点のコードを見たいときは `git show HEAD~1:app/Http/Controllers/TaskController.php` のように
1 つ前のコミットを参照してください。第 11 章の Before / After がそのまま差分になっています。

```bash
git diff HEAD~1 HEAD   # 第11章でやるリファクタリングの全差分
```

### 第 11 章（型付け）の扱い

初学者向けに、**型は本編では最小限にとどめ、動くものを作り切ってから
リファクタリングとして型を入れる** 構成にしています。

- 第 0〜10 章：`$id`、型なしの戻り値。Laravel の流れを覚えることに集中させる
- 第 11 章：`declare(strict_types=1)` / 戻り値の型 / ルートモデルバインディング /
  FormRequest / PHPDoc を、**テストを緑に保ったまま** 入れていく

「テストがあるから安心して構造を変えられる」を体験させるのがこの章の狙いなので、
**第 10 章で全部緑になっていない学生を第 11 章に進ませないでください。**

型に厳しいコードを最初から書かせたい場合は、`solution` ブランチの最終コミットの
コードを第 4 章以降のコード例と差し替えれば対応できます（`use` 文と型名の説明が増えます）。

なお `declare(strict_types=1)` を入れても `/tasks/3/edit` の `'3'` が
`Task $task` や `int $id` に渡って壊れることはありません。
`strict_types` は宣言したファイルではなく **呼び出しを書いたファイル** で判定され、
コントローラを呼ぶのは `vendor/` 側（非 strict）だからです。
第 11 章にこの説明を入れてあります。

## 事前準備のお願い（受講者へ告知する内容）

当日つまずく最大の要因は環境です。**事前に済ませてもらってください。**

1. XAMPP をインストールし、MySQL が起動できることを確認
2. Composer をインストールし、`composer -V` が通ることを確認
3. Git をインストール
4. エディタ（VS Code 推奨）をインストール
5. `php -v` が **8.0.2 以上** であることを確認

Windows で `php -v` が通らないケースが多発します。
PATH に `C:\xampp\php` を追加する手順を、事前案内に含めておくと安全です。

## 配布方法

```bash
# 講師側：リポジトリを用意して push
git push origin main
```

```bash
# 受講者側
git clone <URL> todo-app
cd todo-app
composer install
```

- `vendor/` は **コミットしていません**。当日 `composer install` を各自で実行してもらいます
- 会場のネットワークが不安な場合は、`vendor/` を含めた ZIP も用意しておくと保険になります
- `.env` もコミットしていません（`.env.example` からコピーさせます）

## 教室 PC がシャットダウンでリセットされる場合

受講者 PC が毎回まっさらに戻る環境を前提に、教材を組んであります。

### 毎回のセットアップ

README の冒頭に **「セットアップ手順（クローンから起動まで）」** を置き、
末尾にコピペ 1 回で 7 手順が通るブロックを載せてあります。
2 回目以降はここを見せるだけで済みます。

```
XAMPP で MySQL を Start
  → git clone → composer install → .env 作成 → key:generate
  → todo_app を作成 → php artisan migrate → php artisan serve
```

**毎回 `composer install` が走ります。** 30 人が同時に叩くと回線を圧迫するので、

- 事前に `vendor/` 入りの ZIP を USB か共有フォルダに置いておく
- または Composer のキャッシュがリセットされない場所にあるか、事前に確認しておく

のどちらかを用意しておくと安全です。

### 受講者の作業が消える問題

**授業の終わりに保存させないと、次回ゼロからやり直しになります。**
README と第 0 章の両方に「帰る前に必ずやること」を入れてありますが、
講師側からも毎回リマインドしてください。

- **方法 A**：各自の GitHub リポジトリに push（推奨。事前にアカウントを作らせておく）
- **方法 B**：`todo-app` フォルダを USB / クラウドにコピー（`vendor/` は消してよい）

授業の残り 10 分を「保存タイム」として確保しておくのが確実です。

### 章の切れ目で講師がリカバリする

前回の続きが復元できなかった受講者が出た場合、`solution` ブランチから
該当章までのコードを渡せば追いつけます。

```bash
git switch solution
git show HEAD~1:app/Http/Controllers/TaskController.php   # 第10章時点
```

### composer install が遅い／落ちる場合

Laravel 9 はサポートが終了しているため、Composer 2.9 以降では
セキュリティ勧告によりインストールがブロックされます。
このリポジトリの `composer.json` では、次の設定を入れて回避済みです。

```json
"config": {
    "audit": {
        "block-insecure": false
    }
}
```

**この教材は学習用です。本番環境では Laravel 9 を使わないよう、受講者に一言添えてください。**

## 自己採点テストについて

```bash
php artisan test            # 全部
php artisan test --filter=ch04   # 特定の章
```

- 全 14 件。第 10 章まで終わると全部緑になります
- メモリ上の SQLite で動くので、MySQL の開発データは壊れません
- 章と対応するテスト名（`test_ch04_...`）にしているので、進捗確認に使えます

進捗を確認したいときは、受講者に

```bash
php artisan test
```

の実行結果（`Tests: 8 passed, 6 failed` の行）を報告してもらうのが手早いです。

## アレンジのヒント

- **時間が足りないとき**：第 10 章の「完了済み一覧」を省略し、フラッシュメッセージだけにする
- **時間が余るとき**：第 12 章の課題 1（期限）を全員でやると達成感が出る
- **DB を SQLite に変えたいとき**：`.env` を

  ```env
  DB_CONNECTION=sqlite
  DB_DATABASE=（DB_HOST 以下の行はコメントアウト）
  ```

  にして `database/database.sqlite` を空ファイルで作れば、MySQL なしでも全章動きます。
  環境構築でハマる時間をゼロにしたい場合の選択肢です。
- **ペア作業にするとき**：ドライバ／ナビゲータを章ごとに交代させると、両方が手を動かせます
